# 猫じゃらしロボのESP32-S3制御ファームウェア

`cat_robot.ino` は、配線済みのAE-DRV8835-S、左右encoder、Smraza S51を扱うArduinoスケッチである。ESP32自身がパスワード付きWi-Fiアクセスポイントを作り、接続したPCやスマホのブラウザから操作する。起動時はモータ出力とサーボ信号を0にする。

標準の手動画面は従来どおりPWM出力割合で操作する。1.1.0では、実測校正値を登録して使う左右のPI速度制御、学習済み回帰モデルによる補正、時刻付きの計測APIを追加した。未校正の状態では速度制御を受け付けず、実測モデルがなければ学習モードを受け付けない。猫の認識は含まない。

今回の実機の車輪周長とencoderの1回転あたりのカウントは、まだ測定していない。電流とトルクのセンサーは実装していない。2026年10月31日にCOM側から1.1.0を書き込み、起動時の操作無効、左右PWMとサーボ出力0を確認した。USBシリアルで直近16件ずつ2回の計測記録を保存し、各応答内の記録間隔はすべて20 msであった。走行中のWi-Fi経由の連続収集は未確認である。

## 接続と操作

1. ESP32を起動する。通常の起動では走行しない。
2. USBシリアルへ `wifi` と改行を送ると、Wi-Fi名、パスワード、URLが表示される。パスワードは初回起動時に生成し、ESP32内に保存する。Wi-Fiへ接続できる端末は1台である。
3. PCまたはスマホで表示されたWi-Fiに接続する。インターネット接続がないという表示は、このロボットへの直接接続であるために出る。
4. ブラウザで `http://192.168.4.1/` を開く。
5. 「操作を有効にする」を押す。走行ボタンを押している間だけ走行する。サーボは「サーボを動かす」を有効にしてから位置スライダーで操作する。
6. 「すべて停止」を押すと操作を無効にし、モータ出力とサーボ信号を止める。再開には再度「操作を有効にする」を押す。

前進や旋回の向きが実際の取り付けと合わない場合は、「すべて停止」の後、「停止中の設定」で左右の反転を変更して保存する。直進と旋回は合っていて前後だけが逆の場合は「前後を入れ替える」を押すと、左右の反転をまとめて変更し保存する。モータの線を付け替える必要はない。

操作ボタンの文字選択、長押しメニュー、文字のドラッグを無効にする。Safari向けに、走行ボタンのtouchstartの既定動作も抑止する。ボタンを離した場合やpointercancelを受けた場合に走行指令を0へ戻す。実機のSafariでの長押しは未確認である。

サーボ信号は50 Hz、1400〜1600 µsである。Smraza S51の実測した角度ではなく、中心付近から操作するための初期範囲である。サーボの保持力や機構の可動範囲は未検証である。

## GPIO

| ESP32-S3 | 接続先 | 用途 |
| --- | --- | --- |
| GPIO4、GPIO5 | DRV8835 AIN1、AIN2 | 左方向、左PWM |
| GPIO6、GPIO7 | DRV8835 BIN1、BIN2 | 右方向、右PWM |
| GPIO15、GPIO16 | 左encoder C1、C2 | 回転のカウント |
| GPIO17、GPIO18 | 右encoder C1、C2 | 回転のカウント |
| GPIO13 | サーボ黄色 | サーボ信号 |
| GPIO1 | 30 kΩと10 kΩの分圧中点 | 設定で有効化した場合のみ電池電圧を読む |

DRV8835のVCCとMODEは3V3、VMはモータ用6 V、GNDは電源側の共通GNDである。左右encoderのVCCはユーザー報告の3V3配線を前提とする。encoderの3.3 V動作仕様は未確認である。

## 停止条件と範囲

- 操作指令を300 ms受信しないと操作を無効にする。状態表示の取得だけでは期限を延長しない。操作画面は有効な間、100 msごとに指令を送る。
- 10 ms周期を指定した独立タスクで出力と停止条件を処理する。HTTP処理が止まっても、タスクが動作していれば期限切れで停止する。実機の最悪応答時間を測定した値ではない。
- PWM出力15%以上でencoderの変化が800 ms途絶えた場合は停止する。原因を車輪の拘束と断定しない。encoderの不動作や始動不足でも停止する。モータ出力は最大50%、初期画面は20%である。
- 指令には操作有効化ごとの世代と連番を付ける。停止後に遅れて届いた指令、古い連番、期限切れ指令では再開しない。
- 回転方向を反転するときは、出力を0まで下げてから逆方向へ増やす。出力0の指令と停止条件では減速待ちをせず0にする。PHASE/ENABLEモードのPWM 0はブレーキである。
- Wi-Fiはランダムな16文字のパスワードを使う。操作APIには起動ごとのトークンを要求する。外部のWebページからの単純なフォーム送信では操作できない。通信は独立したアクセスポイント内のHTTPであり、インターネット経由の遠隔操作機能はない。
- 電池の分圧回路は接続が未確認のため、電圧監視の初期設定は無効である。「30 kΩ／10 kΩを接続済み」を有効化した場合、公称比4倍の電圧が6.8 V未満で200 ms続くとソフト停止する。ADC値は未校正である。無効時は電池のソフト停止を行わない。

停止はソフトウェアによる出力停止であり、CPU停止時の電源遮断、電池の過放電保護、セル単位の監視を実現するものではない。停止時はサーボ信号を止めるが、サーボ電源は接続されたままである。無監視運転の過放電対策は未完了である。

## ビルドと書き込み

Arduino-ESP32 3.3.11の標準ライブラリだけを使用する。PSRAMを使用しない。標準のビルドはネイティブUSB（基板のUSB側）をシリアル入出力に使う。

```sh
sh projects/cat-robot-learning/scripts/build-firmware.sh
```

COM側のUSBシリアル変換器を使う場合は、先頭に `--com` を付ける。`CDCOnBoot=default` を選び、シリアル入出力をUART0へ向ける。2026年10月31日の実機確認はCOM側で行った。どちらもビルドだけでは書き込まれない。

```sh
sh projects/cat-robot-learning/scripts/build-firmware.sh --com
```

実機は2026-10-16にESP32-S3 revision v0.2、flash 16 MB、内蔵PSRAM 8 MB、MAC `28:84:85:5f:14:c8` と読み取った。接続先はその時点で `/dev/cu.usbmodem11201` であった。ポート番号は再接続で変わる可能性がある。

USBと外部5 Vの回路上の分離は実機で確認していない。端子の左右の位置から接続先を推測せず、印字を使う。今回の実機識別でネイティブUSBの通信は成立したが、同時給電の適否を検証したものではない。

## 検証の再実行

`tests/run-control-tests.sh` はPC上で停止条件を検証するシェルスクリプトである。C++17コンパイラとNode.jsが必要である。

```sh
sh projects/cat-robot-wiring-visual/tests/run-control-tests.sh
node projects/cat-robot-wiring-visual/tests/build-control-preview.mjs /tmp/cat-robot-control-preview.html
```

生成したHTMLは、実機へ接続しないブラウザ用の模擬通信環境である。ブラウザで開くと、起動時停止、操作有効化、押す動作と離す動作、サーボ、停止、設定保存を検証してconsoleへ結果を出す。対話的に確認する場合は `node projects/cat-robot-wiring-visual/tests/serve-control-preview.mjs` でローカルの8766番ポートを開く。どちらもシリアルポートを開かない。

## API

`GET /api/status` はJSONで状態を返す。`POST /api/arm` で操作を有効にし、応答の `epoch` を操作指令に使う。`POST /api/command` にはフォーム形式で `epoch`、増加する `seq`、`left` と `right`（−50〜50）、`servo`（0で信号停止、1400〜1600で位置指定）を送る。`POST /api/stop` で操作を無効にする。POSTにはページ内の `X-Robot-Token` が必要である。

USBシリアルの115200 baudでは `status`、`telemetry`、`wifi`、`stop`、`help` を使える。`telemetry` はHTTPと同じJSON形式で直近最大16サンプルを返す読み取り専用の診断であり、連続した全サンプルを送信する機能ではない。走行の連続記録はWi-Fi経由で取得する。停止中に `invert 0 1` を送ると、左の反転なし、右の反転ありを保存する。`invert` の2つの引数は、左と右の反転設定（0または1）である。USBシリアルからの走行指令は実装していない。Wi-Fi名とパスワードを含む実機の設定はgitへ保存しない。

## 直進学習用の機能

今回のCOM接続では、ポートを開き直すとESP32が再起動することを状態応答の起動識別子で確認した。接続後は起動を待ってからコマンドを送り、手回しの計測中は同じポートを開いたままにする。再起動すると回転カウントと計測バッファは初期化される。

実験用のCLIは、隣の `projects/cat-robot-learning/` にある。Apple Siliconで既存ctagsが実行できない場合は、次のビルドを使う。公式ctags 5.8-arduino11を利用者のキャッシュ内でarm64用にビルドし、このコマンドだけで参照する。Arduino15やシステム全体は変更しない。

```sh
sh projects/cat-robot-learning/scripts/build-firmware.sh
```

`GET /api/telemetry?after=連番` は最大16サンプルと、起動識別子、最新の連番、バッファから失われた件数を返す。20 ms周期を目標に、同じ制御タスクから回転数、左右の出力、目標速度、補正率、停止理由、同期LEDの状態を記録する。記録の取得で指令の300 ms期限は更新されない。採取間隔と欠落は保存したデータで確認する。

`POST /api/drive` は既存の認証、`epoch`、`seq` に加えて、`mode`（0=出力指定、1=PI、2=PIと学習補正）、`speed_mps`、`correction`、`pwm` を受け取る。速度制御の内部計算は通信期限を更新しない。出力上限50%、通信断、encoder無応答、電池監視の既存条件を維持し、サーボは停止する。学習時の補正率は左右目標速度を `v×(1−correction)` と `v×(1＋correction)` にする値である。

`POST /api/calibration` は停止中にだけ校正値を保存する。`confirmed=1`、左右の `meters_per_count`、`sign`、`feedforward`、`deadband` と、`kp`、`ki`、`max_speed` を送る。左右のキーには `left_`、`right_` を付ける。`learned_model.h` は未学習の状態で配布し、実測から学習したモデルを明示的に書き出したときだけ置き換える。

同期LEDはGPIO8から220 Ωまたは330 Ωの抵抗、赤LEDのアノードへつなぎ、カソードをGNDへつなぐ。未使用時のGPIO8は入力のままにする。停止中の `POST /api/sync` へ `enabled=1` を送った場合だけ出力にして、0、0.5、1.5秒の位置で点灯を開始する。点灯時間はそれぞれ0.15、0.30、0.45秒である。`enabled=0` で入力へ戻す。実機への追加配線は未確認である。
